# LEO 卫星过境预报（离线版）

一个单文件、零依赖安装的卫星过境预报网页。双击就能用，不需要 Node.js、不需要 `npm install`、不联网也能算。

面向地面站操作：多站址管理、卫星库分组与备注、过境窗口导出 Excel，并附带一套天线指标测试工具。

## 快速开始

双击 `Space.html`，用浏览器打开（推荐 Edge / Chrome）。

数据存在浏览器 localStorage 里，关掉网页不丢。建议用 Edge 在本地打开，可将其安装为应用。

## 目录结构

```
Space.html            主页面，全部应用逻辑（含天线指标测试工具）
lib/satellite.min.js  satellite.js v5.0.0 —— SGP4/SDP4 轨道计算
lib/xlsx.full.min.js  SheetJS —— 导出 Excel
tle_catalog.js        内置 TLE 目录快照（16017 颗活跃卫星，快照日期见文件头部）
使用说明.txt           详细使用说明
```

请保持相对位置不变。

## 功能

- **过境预报**：多卫星、多站址合并计算，按入境时间排序；预测时长可选；可设置「最高仰角 ≥ X°」过滤
- **可视化**：天空方位轨迹图 + 仰角变化曲线，支持过境动画播放
- **卫星库**：自由命名分组、按分组筛选、批量选中；点击展开查看 TLE 两行根数（含历元与更新时间，可一键复制）；可记录数传/遥测旋向与频点
- **多站址管理**：添加多个观测站址并勾选参与预报
- **TLE 更新**：可更新全部、已选或单颗卫星；更新在后台执行，不阻塞预报
- **天线指标测试工具**：天线增益（波束宽度法）、系统噪温（Y 因子法）、G/T、EIRP、指向精度（20 组录入）、频谱仪操作指南、测试记录
- **导出**：过境窗口导出为 Excel（.xlsx）

## 关于 NORAD 编录号：Alpha-5 与 6 位编号

这是本项目处理得最费劲的一块，值得单独说明。

**背景。** 2026-07-11，USSF 编录号达到 100000，此后新入编的目标都是 6 位编号。TLE 格式的编录号字段是**固定 5 列字符宽**，装不下 6 位数字。CelesTrak 因此对编录号 ≥ 100000 的对象**不再提供 TLE 格式**（请求返回 404 `No GP data found`），只提供 OMM（JSON / XML / CSV / KVN）。

**Alpha-5** 是把 5 列字宽扩展到 339999 个编号的过渡方案：首字符改用字母，`A`=10、`B`=11……依次类推，**跳过字母 I 和 O**（避免与数字 1、0 混淆）。于是 `A0000` = 100000，`Z9999` = 339999。

**本项目的处理：**

- **编录号在程序内部统一为十进制字符串。** `A0000` 与 `100000`、`00900` 与 `900` 都视为同一颗卫星；添加、搜索、更新时两种写法都能用。旧数据在加载时自动迁移。
- **只有写进 TLE 两行根数时才用 Alpha-5 的 5 列形式。** 这是硬约束：写成 6 位数字会让整行变 70 列、后面每个固定列**全部错位**，而 `parseFloat("0. 001234")` 会**静默返回 0** —— 轨道算错却不报任何错。这是该项目里最危险的一类失败。
- **新增 OMM → TLE 合成。** 本项目使用的 satellite.js v5 只有 `twoline2satrec`（没有 `json2satrec`），且整个应用的持久化结构就是两行根数文本。因此取回 OMM 后合成 TLE，而不是换掉传播库。合成结果经过**全量回归**：用内置快照里 16017 条真实 TLE 反推 OMM 字段再重新合成，`line1`/`line2` 均逐字节一致，`twoline2satrec` 的 13 个输入量差异为 0。
- **必需字段缺失时明确报错。** 升交点赤经等字段取不到值时会直接报错，绝不静默按 0 处理（否则会算出一条轨道面完全错误、但页面看起来正常的卫星）。
- **编录号 > 339999 无法写入 TLE**，程序明确报错而非截断。

## 数据源

输入 NORAD 编号取数时，按以下顺序依次尝试：

1. **自定义 OMM 数据源**（若已配置）
2. 本地代理 `/api/tle?id=`（仅 http(s) 打开时）
3. **CelesTrak TLE** —— 仅当编录号 < 100000
4. **CelesTrak OMM**（JSON，失败再试 CSV）
5. 第三方跨域 TLE API
6. **内置目录快照**（完全离线时的兜底）

某一档超时后，本次会话内会跳过它，避免「更新全部」每次都耗满超时。重新联网后可执行 `resetTLESources()` 恢复重试。

### CelesTrak 连不上怎么办

若更新提示各数据源**「超时」**，说明本机网络到 `celestrak.org` 不通（国内较常见）。值得注意的是：这时 5 位编录号的卫星其实一直在用**内置快照兜底**，不容易察觉，而 ≥100000 的目标不在快照里，就彻底取不到。

解决办法二选一：

**（一）配置自定义数据源。** 打开「卫星库」面板里的「⚙ 数据源设置」，填入任意返回 OMM 的数据源，程序会优先使用它。URL 模板中 `{id}` 为十进制编录号，`{key}` 为 API Key。已预填 [KeepTrack](https://keeptrack.space/api) 的模板（免费注册可取 Key）：

```
https://api.keeptrack.space/v4/sat/{id}/omm?apiKey={key}
```

填好后点「保存数据源」，可先点「测试数据源」用 ISS #25544 验证连通性。模板含 `{key}` 时 Key 放在 URL 里（简单请求，`file://` 打开时不会触发跨域预检，更容易连通）；不含则自动改用 `X-API-Key` 请求头。

> API Key 仅存本机浏览器 localStorage，**不写入任何文件**，因此整个文件夹仍可安全分享。

**（二）手动粘贴 OMM。** 在能联网的环境打开：

```
https://celestrak.org/NORAD/elements/gp.php?CATNR=100465&FORMAT=JSON
```

（把 `100465` 换成目标编录号——注意用十进制，CelesTrak 不认 Alpha-5 写法。）把返回内容整段复制，粘贴到页面「或手动粘贴 TLE / OMM」框即可。支持单条 JSON、JSON 数组、CelesTrak CSV，也兼容 Space-Track 带 `TLE_LINE1/2` 的格式。这条路完全不依赖网络，始终可用。

## 排查

更新失败时，提示里会列出**每一档数据源的尝试结果**（哪一步超时、哪一步返回什么状态码），不再只是一句「获取失败」。

需要更细的信息，按 F12 打开控制台执行（编录号任意写法）：

```js
diagTLE('A0465')       // 逐个数据源打印 HTTP 状态、耗时与响应内容
resetTLESources()      // 清除「本次会话跳过」的记录，重新尝试全部数据源
```

`diagTLE` 输出中 API Key 会被遮成 `***`。

## 已知限制

- 内置快照为 TLE 格式，**不含编录号 ≥ 70000 的对象**，且会随时间老化、精度下降。断网时 ≥100000 的目标无法获取。
- 快照日期见 `tle_catalog.js` 头部，仅供离线兜底，需要精确预报时请手动更新。
- 编录号 > 339999 无法表示，程序会明确报错。
